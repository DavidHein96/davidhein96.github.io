[Opening paragraph — set up why this matters and what the reader will get out of this post.]

This post tells the story of how our clinical data extraction approach evolved across real projects — from naive prompting to structured output to function calling with Pydantic validation. Each transition was driven by hitting a wall with the previous approach, and the failure modes are instructive.

If you’ve read my earlier post on our npj Digital Medicine paper, this picks up where that left off. The error ontology we developed there — categorizing failures by source, severity, and context — turns out to map almost perfectly onto why each approach breaks.

     The model produces VALID JSON that is WRONG. Examples to look for in your experience:
     - Model stuffing data into the wrong field because the right field didn't exist
     - Losing nuance: "probably clear cell, but could be papillary" → forced into one value
     - Optional fields: model hallucinating values rather than leaving null
     - Conditional fields: model filling in fields that shouldn't apply to this report
